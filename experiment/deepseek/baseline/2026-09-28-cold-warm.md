# DeepSeek baseline: one cold/warm pair through the existing proxy path

**Experiment** `deepseek/baseline` · **Date** 2026-09-28 · **Stage** Baseline, no intervention

## Path used

`replay serve -upstream https://api.deepseek.com`, the existing OpenAI-compatible
`/v1/chat/completions` route. **No new adapter was written and no file was changed
to execute this.** DeepSeek was already supported and already conformance-tested
against bytes captured from `api.deepseek.com` on 2026-09-05.

## Workload

One request body, 5,548 bytes, sent twice against an identical prefix so the
second call could hit the provider's cache.

- model requested: `deepseek-v4-flash`; model returned in the body: `deepseek-flash`
- system: "You are reviewing a measurement architecture. Answer in at most 40 words."
- user: the first 120 lines of `docs/SURFACE-REGISTRY.md` plus one question
- `max_tokens` 80, `stream` false
- ledger isolated to a scratch directory; the operator's `~/.replay/ledger` was not written to

## Evidence OBSERVED, as returned by the provider

|---|---:|---:|
| `prompt_tokens` | 1,450 | 1,450 |
| `prompt_cache_hit_tokens` | 0 | **1,280** |
| `prompt_cache_miss_tokens` | 1,450 | 170 |

The cold call is genuinely cold: 0 cached. The fixture README records an earlier
attempt where a "cold" capture was actually warm at 13,952 cached tokens, so this
was checked rather than assumed.

## Replay measurement

Both requests were ingested. The normalization is correct and is the load-bearing
result:

| ledger field | cold | warm |
|---|---:|---:|
| `input_tokens` | 1,450 | **170** |
| `cache_read_input_tokens` | 0 | **1,280** |
| `cache_creation_input_tokens` | 0 | 0 |
| `output_tokens` | 80 | 80 |
| `thinking_tokens` | 36 | 66 |
| `latency_ms` | 1,501 | 1,003 |

DeepSeek counts **inclusively**: its `prompt_tokens` of 1,450 already contains the
1,280 cached. Replay records `input_tokens: 170`, the uncached remainder, with the
cached share beside it. Copying the provider's own "prompt" figure into a
normalized fresh-input field would have double-counted the cache, and the error
would be largest on exactly the sessions that cache best. That is the defect the
2026-09-05 spike recorded Langfuse shipping.

`replay cost` over this ledger: `totalRequests: 2`, `unjoinableRequests: 2`,
`unpriced: 1`, `tasks: 0`, `totalUsd: 0`.

## NOT_MEASURED

- **Dollars.** `internal/cachemodel` carries no DeepSeek entry, so no price table
  applies and no cost is derived. `totalUsd: 0` here means unpriced, not free.
- **Throughput and TTFT.** Not exposed by a non-streaming response.
- **Task/session joining.** Both records are `unjoinable`; `replay cost` reports
  tasks from transcript sessions and these are proxy-ledger records.
- **Outcome quality.** The answers were not evaluated. Whether the model's
  response was useful is unmeasured.
- **Cost of this run.** Unknown to Replay; the provider was not asked.

## Credential handling

The key was supplied for this task and used in memory only. It was written to no
file and appears **0 times** in the ledger, the spend file, and the proxy log;
the ledger contains no `Authorization` field. Note that the proxy documents this
path as EXPERIMENTAL and UNMASKED: `-mask` cannot read the OpenAI-compatible body
shape, so a key inside such a request body would reach the provider in clear. The
key here travels in the header, which is forwarded rather than logged.

## Outcome

`COMPLETE` for ingestion and normalization. `PARTIAL` as an economic baseline,
because no price table applies.

## Reproduction

```
replay serve -upstream https://api.deepseek.com -listen 127.0.0.1:4071 -ledger <dir>
curl -sS -X POST http://127.0.0.1:4071/v1/chat/completions \
  -H 'Content-Type: application/json' -H "Authorization: Bearer $DEEPSEEK_API_KEY" \
  --data @request.json
replay cost --json <dir>
```
