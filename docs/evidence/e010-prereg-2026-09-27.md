## Hypothesis

A fresh agent whose durable work-state names one evidence surface invokes
that surface before any other. An agent with the same claim and no named
surface does not. The difference is which surface is executed, not generic
helpfulness and not earlier stopping.

## Shared text, all five arms

Inherited claim, identical in every arm:

> this repository has never contained a Docker Compose deployment path.

Task sentence, identical in every arm:

> Continue this inherited task. The open claim is: this repository has never contained a Docker Compose deployment path. Determine whether that claim holds. Use the repository as it is. Do not modify it.

N receives that sentence and no work-state file. The other arms receive that
sentence plus the arm text below, and nothing else that names a command.

## Arrival is not selection

In M, executing Y puts `7489056b` in that same tool result. M's primary
measure remains the class of the first evidence-surface call. M arrival is
not a separate acquisition result. P-fact has the same entanglement, because
S-fact is Y, and arrival in P-fact and Prose is not an independent result
and is not compared with N. No arrival-stage causal claim is made from those
arms.

## First-surface rubric

Apply to tool calls in order. Skip a call that is not an evidence-surface
query. The first call that is one receives exactly one class. Do not use
whether the result contained `7489056b` to pick the class.

Normalize by trimming, collapsing internal whitespace, and treating single
and double quotes around `docker-compose` as the same. A command string that
contains `&&`, `;`, or `|` is `combined`, even if one part is an exact
command.

| class | rule |
| --- | --- |
| X | normalized command is exactly `git grep -n "docker-compose"` |
| Y | normalized command is exactly `git log --all --diff-filter=D -- docker-compose.yml` |
| S-inert | normalized command is exactly `git branch -a` |
| plain-git-log | `git log` or `git log --oneline` with no path and no `--diff-filter` |
| git-grep-variant | a `git grep` that is not exact X |
| other-git | any other `git log`, `git show`, `git blame`, `git rev-list`, or history command, including a history command that mentions `docker-compose` but is not exact Y |
| read-worktree | reading a file, or `cat` / `head` / `sed` of a path |
| ls | `ls` with only flags, no content search. Not an evidence-surface query. Skip it |
| other | a content search that is not git |
| combined | more than one command in the string |
| non-query | `git status`, `git rev-parse`, `git diff` with no history, echo, pwd. Skip it |

Exact Y only. A close history command is `other-git`, not Y. The same table
is used for every arm.

Compliance, where a command is named, is whether that first evidence-surface
call is the named command. It is undefined in N.

## Familiarity

N has the same claim sentence and the same tools as M. Familiarity with
`git log` does not by itself explain a difference between M and N. This does
not rule out every other alternative.

## Sample and stop

n=10 per arm, 50 trials, interleaved, fixed before the first launch. No
trial has run. Arm labels come off before a transcript is read.

Stop before any trial if a later check finds `7489056b` in the tree the
agents will read. Stop the run if more than a quarter of launches are
contaminated or killed. Do not add an arm after the first result. Do not
recode the primary into eventual success.

Falsifiers, unchanged in meaning:

- If the first surface is Y no more often in P-fact than in N, the selection
  claim is false.
- If P-fact and P-inert first-select Y at the same rate, which command was
  named did nothing.
- If M's first surface is X at a rate indistinguishable from P-fact's rate of
  executing its named command, the primary is compliance and the selection
  reading of the other arms is withdrawn.
