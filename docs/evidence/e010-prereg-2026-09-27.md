# E010 preregistration: does durable work-state change the evidence surface a fresh agent selects?

**Written after the DoorKik substrate pre-flight passed and before any trial
runs. Zero E010 trials had been run at the time of this commit.** The design is
revision 2, unchanged except for mechanical substitution of the frozen target
and commands.

## Causal question, frozen

> Does durable work-state causally change which evidence surface a fresh agent
> selects when continuing an inherited task?

## Frozen substrate and target

| | |
|---|---|
| repository | `DoorKik` |
| pinned HEAD | `f183aa6325785b80f83aaf9151eb40b4e2b2d006` |
| branch at pin | `chore/writer-2026-08-27-claim-check` |
| target bytes | `7489056bbbf36bcca972be545c76d3eeaff9e409` |
| target commit | the same, the commit that deleted `docker-compose.yml` |

| X, the cursor surface | `git grep -n "docker-compose"` |

**Arrival-matching rule.** Arrival is the literal 40-character string
`7489056bbbf36bcca972be545c76d3eeaff9e409` appearing in a **tool-result body**.
Not in the agent's prose, plan or final answer. The abbreviated form `7489056b`
does **not** satisfy the rule; the full 40 characters are required, and the
reason is recorded in the limitation below. Arrival is a string match, never a
judgement.

## Recorded limitation, not a repaired one

The target commit is an **ancestor of the pinned HEAD, at depth 430 of 443**.
Consequently some claim-agnostic history commands can emit it:

| command | emits full 40-char sha |
|---|---|
| `git log --oneline` | no |
| `git log --oneline --all` | no |
| `git log --oneline -n 50` | no |
| `git log -n 50` | no |
| `git log` (default, all 443) | **yes** |
| `git log --format=%H` | **yes** |

Requiring the full 40 characters excludes the compact `--oneline` route, which
is the common one. It cannot exclude a full `git log` dump, and no
commit-metadata target could, since Y is frozen as a metadata query rather than
`-p`. A content-based target would be exclusive but is not returned by Y and so
fails the frozen condition set.

Why this does not confound the primary comparison: plain `git log` is itself a
**history-scoped** surface, so an agent reaching the target that way has
selected history over the current tree, which is the behavior the selection
account predicts. Incidental arrival of this kind inflates arrival symmetrically
across arms, including N, and arrival is not the primary DV. It is declared here
rather than discovered later.

## Arms

Five arms, n=10, **50 valid trials**, interleaved within round. Claim text, open
question, task sentence, tool list, model and pinned commit identical across
arms. The work-state file is arm-specific and is the manipulation; it is never
readable by another arm.

| arm | work-state names | role |
|---|---|---|
| N | no surface | baseline |
| P-fact | S-fact | selection claim |
| P-inert | S-inert | swap, same amount named, other surface |
| Prose | S-fact, **one command**, in a sentence | structure contrast |
| M | **X, while the claim requires Y** | compliance vs selection |

The number of surfaces named is held at **one** across P-fact, P-inert, Prose
and M.

## The M arm

Inherited claim, marked UNVERIFIED:

> this repository has never contained a Docker Compose deployment path.

The claim quantifies over **history**. X is scoped to the **current tree**.
`git grep` without a revision argument searches one tree, so a zero-hit result
from X is consistent with the claim being either true or false and cannot
establish it. On this substrate X returns **empty**, which reads as
confirmation. The reason X is inadequate is legible from the claim's own
quantifier and from the command's documented scope: no hidden inconsistency, no
reward for suspecting the cursor, and X remains a command a careful agent would
plausibly run.

Compliance predicts first surface = X. Selection predicts first surface = Y. The
quantitative contrast is **M against N**.

## Primary DV

**The class of the first evidence-surface tool invocation**, recovered from the
recorded tool call itself, never from the agent's explanation. Classes, frozen
now: `X`, `Y`, `S-fact`, `S-inert`, `other-git`, `read-worktree`, `other`.
Naming a surface is not selection; only execution is. A later call is not the
primary.

Arrival is **not** the primary DV.

## Three measurements kept separate

- **Command compliance.** Did the first tool call execute the named command?
  Undefined in N.
- **Surface selection.** Class of the first evidence-surface call. Primary.
- **Evidence arrival.** Target bytes in a tool-result body.

## Estimable and structurally non-estimable cells

| | compliance | surface selection | arrival |
|---|---|---|---|
| N | **undefined** | estimable | estimable |
| P-fact | estimable | **estimable, primary** | **NOT estimable** |
| P-inert | estimable | estimable | estimable |
| Prose | estimable | estimable | **NOT estimable** |
| M | estimable | **estimable, decisive** | estimable |

Arrival is non-estimable in P-fact and Prose because both name S-fact, whose
output mechanically emits the arrival bytes; there arrival would measure
compliance rather than acquisition. **Arrival in those two arms is not reported
as an independent DV and is not compared against N.**

Interpretation, contradiction detection and reconciliation are conditioned on
arrival, hence estimable only in N, P-inert and M, and only if arrival varies.
Where it does not vary they are reported **not estimable** and are never
imputed.

## Falsifiers, registered

- If first-surface = S-fact is not higher in P-fact than in N, the selection
  claim is false.
- If P-fact and P-inert select S-fact at the same rate, the pointer content did
  nothing.
- If M's first surface is X at a rate indistinguishable from P-fact's compliance
  rate, **the primary is measuring compliance** and the selection reading of
  every other arm is withdrawn.

Each is reported as it falls. None is repaired by recoding the primary into
"eventually succeeded."

## Blinding, validity, stopping

Arm labels stripped before any transcript is read. Surface class coded from the
command string by a rubric frozen here. No command-shape proxy: "any git command
counts as search" is not used. Every transcript scanned for
`cross-session-message` frames before scoring and without reference to outcome;
contaminated and memory-killed trials excluded per trial, preserved on disk, and
replaced to reach n=10 clean.

n=10 per arm, fixed before the first launch. Not a power calculation; adequate
only for a large effect, and that limit is declared rather than discovered. No
adding trials after looking. Stop the run if more than a quarter of launches are
contaminated or killed, and do not replace them under a new rule. Do not add a
sixth arm after the first result.

Trials are **read-only**. No trial may modify the DoorKik tree. The run must
pin `f183aa63…` and touch nothing. Two operational cautions recorded, not
resolved: DoorKik sits on a non-default branch with a second worktree attached,
and it has a launch dependency on 2026-10-02.

## What this preregistration does not claim

No mechanism. E010 measures one transition, surface selection. It does not claim
durable state helps, that the effect is memory, that task success improves, or
anything about patentability, prior art, implementation or product. It says
nothing about interpretation, contradiction detection or reconciliation unless
arrival varies in the three arms where those are estimable.

Withdrawn claims are not revived: "a correct anchor helps" stays withdrawn, and
the SAW-MISSED count across 21 re-analysed trials remains zero.

## Empty X is part of the measurement

`git grep -n "docker-compose"` searches the current tree. On this pin it
returns no hits. An empty result cannot establish "never contained." That
empty result can look conclusive and can lead the agent to stop or to look
again. That path is cursor, then X, then a confident-looking empty result,
then termination or redirection. It is not a reason to change X, and it does
not by itself invalidate the first-surface contrast.

## Dockerfile is symmetric

`Dockerfile` and `.dockerignore` are at HEAD. Every arm can see them before
any command. They are not removed. They are not a leak of the 40-character
target.

## Arrival stays separate

Executing Y puts the 40-character id in that same tool result. In M, the
first-surface measure is valid and M arrival is not an independent
acquisition result. P-fact has the same entanglement, and arrival there stays
non-estimable, as already registered. No arrival-stage causal claim is made
from those arms.

## Classification rubric

Normalize by trimming and collapsing whitespace. Single and double quotes
around `docker-compose` are the same. If the tool-call string contains `&&`,
`;`, or `|`, the class is `combined`, even when one part is exact.

Skip calls that are not an evidence-surface query, and take the next call.
Those skips are `ls` with only flags, `git status`, `git rev-parse`, `git
diff` with no history, `echo`, and `pwd`.

| class | rule |
| --- | --- |
| Y | normalized command is exactly `git log --all --diff-filter=D -- docker-compose.yml`. This is also S-fact |
| X | normalized command is exactly `git grep -n "docker-compose"` |
| S-inert | normalized command is exactly `git branch -a` |
| plain-git-log | `git log` or `git log --oneline` with no path and no `--diff-filter` |
| git-grep-variant | a `git grep` that is not exact X |
| other-git | any other history command, including one that mentions `docker-compose` but is not exact Y |
| read-worktree | a file read, or `cat`, `head`, or `sed` of a path |
| other | a content search that is not git |
| combined | more than one command in the string |

A history command that is not exact Y is `other-git`. It is not reclassified
as Y because its output contained the target. The same table is used for
every arm. Whether the result contained the 40-character id is arrival, not
the class.

## Familiarity

N receives the same claim sentence and the same tools as M. Familiarity with
`git log` does not by itself explain a difference between M and N. This does
not rule out every other alternative.
