# replay simulate: the P0 historical policy simulation, built and gated

**2026-10-03. The smallest surviving implementation from the ten-pass implementation
board: replay a recorded ledger through the proxy's own spend guard under a cap you
supply, and say which recorded requests would have been refused. Nothing predicted,
nothing routed, nothing stored, no network, no new secret.**

Labels: **SIMULATED** is every result this command prints. **MEASURED** is a figure a
registered oracle produced. **OBSERVED** is what a run printed.

---

## 1. The claim, exactly

Given an existing ledger (the `.jsonl` files `replay serve` writes) and an explicit
alternative spend-cap policy (a JSON document with any of `maxSessionTokens`,
`maxDayTokens`, `maxSessionUsd`, `maxDayUsd`, the four caps `serve` takes as flags),
`replay simulate --policy <file> <ledger-dir...>` deterministically identifies which
recorded requests would have been refused under that policy.

Additional outputs are existing, already-supported measures and nothing else:
requests evaluated, requests that would have been refused, sessions affected, and the
list price of the refused requests at the dated price table. The last is labelled for
what it is: what those requests cost when they ran, not a saving, because what the
agent would have done when refused is not recorded anywhere.

Not claimed, and tested as absent from the output: savings, forecasts, future spend,
provider capacity.

## 2. The production path

```text
replay simulate --policy p.json ~/.replay/ledger
  → cmd/replay/main.go dispatch()          case "simulate"
  → cmd/replay/simulate.go runSimulate     flags via the shared parseArgs; --policy required; ≥1 ledger dir required
  → loadSimulatePolicy                     strict JSON (unknown key refused), negative cap refused, no-cap document refused
  → internal/ledger.ReadRecords            every ledger file in each directory, as the proxy wrote them
  → population                             records the proxy forwarded with a usage; refused-at-the-time, usage-less and
                                           unreadable records counted and not replayed
  → sort by (timestamp, session, request id)
  → internal/proxy.NewSpendGuard + SetClock(record time) + Check / Record
  → internal/proxy.ListCost                the proxy's pricing, dearest-rate upper bound for an unpriced model, exactly as the proxy
  → decision records                       session, request id, timestamp, model, list price, upper-bound flag, admitted or refused, the guard's reason
  → human report or --json (schema replay.simulate.v1, simulated: true, policy hash)
```

The two exports added to `internal/proxy` are a wrapper (`ListCost`) and a clock
setter (`SetClock`); the deciding code is the shipped guard, unchanged. The policy
identity is the SHA-256 of the cap's canonical form, truncated to twelve hex
characters, with no registry.

## 4. The real-ledger artifact

The ledger `replay serve` has written on this machine: 5 files, 17 records, the
population the quota census counted. Read only; its digest was identical before and
after both runs.

**Policy `db60bf2fcd4c`, session cap $5.00 (conservative).**

```text
SIMULATED: policy db60bf2fcd4c (session $5.00) replayed over 15 requests in 4 sessions from ~/.replay/ledger,
at list prices dated 2026-09-07 (caching rules anthropic-2026-09-05).

  admitted   15
  refused    0   in 0 session(s)
  not replayed: 0 refused by the proxy at the time (their usage was never observed),
  2 without usage, 0 unreadable file(s). 0 request(s) ran on a model the price
  table does not carry and are counted at the dearest known rate, as the proxy counts them.
```

**Policy `bbc9944ede24`, session cap $0.10 (chosen to bite, to show the mechanism).**

```text
  admitted   7
  refused    8   in 1 session(s)
  list price of the refused requests: $0.9348. That is what they cost at list when
  they ran; what the agent would have done instead is not recorded.
```

Population: 15 requests, 4 sessions, 0 historically refused, 2 without usage, 0
unpriced. Per-session list totals on this ledger: $1.07, $2.77, $2.04, $0.37; the
$0.10 cap reaches the one session whose second request already exceeded it, and
refuses its remaining eight. Every figure is SIMULATED and carries its population.

## 5. The commercial experiment, status

The pre-registered test from the ten-pass review, unchanged: ten existing users, thirty
days, `replay simulate --policy` over their own ledger; **kill threshold: fewer than
three change or enable a cap because of a simulation they ran** (experiments 9 and 10).

**Not yet runnable.** Missing: (1) a release carrying the command (this commit is on a
branch, unreleased); (2) ten identified users with a proxy ledger, which this
repository has no list of and must not build a customer system to obtain; (3) the
observation itself, which is a question asked of each user at day thirty, recorded by
hand. Nothing about the threshold moves because of anything measured here, including
the real-ledger run above, which is one machine and one operator.
